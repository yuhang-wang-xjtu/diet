# 轻衡 · 安卓热量、营养与体重记录

独立原生 Android 应用，Kotlin + Android View，最低 Android 8.0。无需账号，SQLite本地保存健康数据；联网仅用于用户主动检查GitHub更新及下载APK，不上传健康记录。

[下载最新正式版APK](https://github.com/yuhang-wang-xjtu/diet/releases/latest)

## 功能

- 应用更新：点击检查最新正式Release、查看发布说明、下载APK并通过系统确认安装；验证大小、GitHub提供的SHA-256、包名、版本和当前签名。支持查看下载状态及重试，详见[更新与发布说明](docs/app-updates.md)。

- 自动计算：填写年龄、性别、身高、体重、全天活动水平，得到BMR参考、TDEE、BMI及蛋白质/碳水/脂肪目标；默认维持体重，更新体重后重算，保留手动覆盖。详见[计算规则与依据](docs/body-estimates.md)。

- 今日概览：饮食摄入、额外运动消耗、日常消耗和估算热量缺口。
- 日期选择：切换日期，补记或修改历史记录。
- 饮食：按早餐、午餐、晚餐和零食分组，支持添加、编辑、删除；旧记录显示在“未分类”。
- 三餐提醒：默认每天本地时间 09:00 / 13:00 / 19:00，可修改或关闭；点击通知打开对应日期和餐次的输入界面，通知按钮支持推迟 30 分钟或标记“这一餐没吃”。
- 历史回顾：可按日期查看食物与营养记录，提供历史食物日期列表；没吃标记可撤销。零食随时手动录入，计入当日热量与营养，不提醒。
- 营养：每条饮食可录入蛋白质、碳水化合物、脂肪的实际摄入克数；概览及记录页按所选日期合计，并对比每日目标与完成进度。
- 快捷食物：离线内置米饭、馒头、番茄、鸡蛋、牛奶、香蕉及油盐糖酱油共10个条目，另有可修改的番茄炒蛋示例配方，支持搜索与按克/份量换算。
- 我的快捷食物：可直接填写名称、参考份量、热量、三大营养素和钠，设置每个/每份的克重；支持编辑、复制和删除。
- 原材料配方：从原料/佐料列表添加，或输入“两个鸡蛋、一个西红柿、10g盐、10g花生油”等文字；校验后展示各项份量与营养合计，保存为快捷配方重复使用。
- 运动：支持自定义种类/强度、每分钟或每小时消耗率 × 时长，区分活动消耗与含静息总消耗；支持保存快捷运动及编辑删除，兼容原有直接输入总消耗。
- 每日步数：授权后读取健康连接的日期汇总，按天覆盖更新；可自动同步当天并补齐最近7日可用数据，也可手动补录。按体重、强度和步频估算步行净消耗，支持扣除手动运动重叠步数及按天关闭计热。
- 无健康连接设备：可主动启用手机本机计步，授予身体活动权限后通过前台服务记录传感器增量；从启用后开始，不读取小米私有数据或手环历史。支持健康连接权限/数据源诊断及单一来源选择，空结果不覆盖缓存。
- 体重：每日一条，重复保存更新；最近 30 天按真实日期间距绘图，提供全部历史记录。
- 设置：个人资料与自动/手动消耗模式，自定义营养目标；CSV导出饮食、营养、运动、体重、资料、基准、目标与计算规则。

## 营养统计与目标

营养字段填写本次食用份量的总克数，不是每 100 g 含量。空白表示未知，0 表示该项确实为零；旧记录升级后保持未知，不会虚构营养数据。页面分别显示每项已填摄入合计、未填条数和参考目标；进度条最多显示 100%，文字保留真实完成百分比，目标不是摄入上限。饮食总热量仍独立填写，不根据三大营养素重新推算，以便使用包装上的实际热量。

自动模式使用Mifflin–St Jeor静息代谢公式估算BMR参考，乘全天活动系数得到TDEE，再按蛋白质20%、碳水50%、脂肪30%分配维持体重热量。自动模式缺口=TDEE−摄入，运动与步数只展示，不再次叠加。范围、来源和限制见[计算说明](docs/body-estimates.md)。

手动模式中，蛋白质未设自定义目标时，使用所选日期当天或之前最近体重 × 0.83 g/kg/天，参考 [EFSA 健康成人蛋白质群体参考摄入量](https://www.efsa.europa.eu/en/press/news/120209)；碳水和脂肪留空只统计。不使用未来体重。两个模式均优先使用自定义营养项，清空并保存恢复当前模式默认规则。一般成人参考不是个体处方，孕哺期、未成年人或疾病相关需求应使用专业目标。

自定义目标和计算模式统一应用于所有日期，修改后历史对比也会更新；实际摄入不变。个人资料按日期保存，第一份资料之前不自动推算。数据库支持从v1–v6升级至v7，保留原饮食、运动、体重与设置。当前正式版0.1.7（versionCode 10）可使用相同签名覆盖旧包，保留记录；不要先卸载旧版。此前开发包使用1.x名称，需先手动下载0.1.7覆盖一次，之后按0.x递增发布并使用应用内更新。默认GitHub更新源为[yuhang-wang-xjtu/diet](https://github.com/yuhang-wang-xjtu/diet)，可在设置中修改或清空。

## 运动与每日步数

在今日或记录页的“每日步数 · 步行”卡片连接健康连接。首次授权后默认打开应用更新当天，自动同步时每天还会尝试补齐最近7日。设备不支持、未授权或无数据时明确提示并支持手动填写。自动同步不会覆盖手动修正；需要覆盖时主动刷新并确认。

小米运动健康若没有健康连接入口，轻衡无法通过这条路径取得小米数据。可在步数卡片选择“启用手机本机计步”，允许身体活动权限，携带手机走几步后点“刷新该日本机步数”。后台计步使用常驻前台服务，重启或系统清理后重新打开应用恢复；可在系统应用信息中检查权限与后台省电限制。启用之前的小米步数不会导入，手机与手环数值可能不同。详细限制和官方直连接入条件见[步数说明](docs/exercise-and-steps.md)。

步行净消耗使用 `(MET−1) × 体重kg × (有效步数/步频) ÷ 60`，默认3.8 MET、100步/分钟。强度和步频可修改，参数不是实测；没有体重或步数时不推算。自动TDEE模式不叠加步行和手动运动；手动模式下，如果基准已含走路，请关闭当天步行计热。手动运动也产生步数时，填写“与当日总步数重叠的本次运动步数”进行扣除，避免再按步行加一次。

运动支持kcal/分钟和kcal/小时两种输入；活动消耗直接乘时长，含静息总消耗先按体重扣除静息部分。可以保存不同运动种类和强度对应的快捷消耗率；固定单位时间消耗不会随体重自动调整。详见 [步数与运动计算说明](docs/exercise-and-steps.md)。

## 快捷记餐与配方估算

在今日、记录页或任意食物录入表单中打开“快捷食物 / 原材料配方”。选择食物并填写实际份量后，热量、三大营养素、钠和份量来源会填入记餐表单；核对日期、餐次后点保存。选择食物本身不会直接产生记录，所以不会同时累计原料和整道菜两份热量。

“＋自定义食物”支持任意参考克重对应的营养数值；例如包装每100g或一份150g均可。热量单位为kcal，三大营养素用g，钠用mg。钠不知道可留空，其他营养确实为零时填0；食盐等0 kcal食物也能保存。自定义快捷食物可作为配方原料。

“＋原材料配方”按每项原料的实际可食用量相加。没称整锅熟重时，只按0.5锅、1锅等比例记录；填了熟重后才能按吃掉的熟食克数分摊，不把生料总重假装成品重。“个、碗、杯、勺”都标注估重，可以改用克数，或复制条目调整自己的单位重量。ml不默认按g换算。

文字输入是有限规则解析，支持常见原料名、部分中文数字、g/克/kg和匹配的个/根/碗/杯/勺/份。遇到未知名称、同名不明确或不支持的单位时整段不添加，提示从列表选择或先建自定义原料。保存前会要求处理尚未加入的文字，避免漏算原料。

自定义食物、配方和原料营养快照离线保存。编辑或删除快捷项不会改变历史食物的已存数值。配方计算假设原料都进入成品，不自动推断锅内残油、弃汤或烹调损失。现阶段跟踪热量、三大营养素和钠，不覆盖全部微量营养素。

数据来源、每100g数值、单位估重和计算示例见 [食物数据说明](docs/food-sources.md)。内置番茄炒蛋为演示配方，可修改，并非某道菜的统一营养值。

## 提醒与餐次

首次打开默认启用三餐提醒，Android 13+ 会请求通知权限；拒绝后可通过应用设置的“通知权限与声音设置”进入系统设置开启。通知点击直接使用 Activity PendingIntent 跳转表单，自动选中原来的日期与餐次；通知本身提供“推迟30分钟”和“这一餐没吃”两个操作。

保存某餐食物或标记没吃后，取消该餐的推迟提醒并关闭对应通知，其他餐次与明天的提醒不受影响。提醒到达时会再次检查本餐是否已记录或没吃，避免已完成后重复打扰。已记录食物的餐次不能被旧通知误标为没吃；给已标记没吃的餐次补录食物会清除没吃标记。没有食物和没有明确标记没吃的餐次显示“待记录”，不会自动当成零摄入。

推迟是从点击按钮起 30 分钟，再次点击可再次推迟。推迟排程保存到本机，跨午夜时仍对应原日期的那一餐。重新打开应用、重启手机、升级应用、改变系统时间或时区后，会恢复每日提醒和已有推迟排程。日常提醒按本地日历计算下一次时间，不用固定 24 小时相加；过去日期的普通提醒不补发。普通提醒被系统延迟到次日时会丢弃，明确推迟的提醒则保留原餐日期。

Android 12+ 如未授权“闹钟和提醒”，使用非精确 `AlarmManager`，系统可能延后提醒；设置页可进入授权界面，授权后自动重排。强行停止应用和部分手机的省电/后台限制仍会影响投递，重新打开应用可恢复排程。关闭提醒会取消三餐排程、推迟提醒和可见通知；重新开启只排未来的普通提醒。

平台依据：[Android 闹钟与精确定时](https://developer.android.com/develop/background-work/services/alarms)、[通知运行时权限](https://developer.android.com/develop/ui/compose/notifications/notification-permission)。本功能是手机本地通知，不依赖聊天提醒或服务器。

CSV 包含餐次、钠、份量与配方说明，自定义快捷项另按“快捷食物参考份量”导出完整JSON以留存配方；当前不支持导入。没吃标记单独列出，不虚构营养数值。

## 计算口径

自动模式：估算缺口 = 全天总消耗TDEE − 饮食摄入。

手动模式：估算缺口 = 日常消耗基准 + 单独记录的额外运动消耗 − 饮食摄入。

手动模式日常消耗基准由用户填写，不应重复包含另记的运动与被计入的步行。基准统一适用于所有日期。自动模式活动已经包含在TDEE中，不再叠加步行或运动。正数为缺口、负数为盈余；缺少有效消耗数据时不显示缺口。没有记录的摄入按0处理，不完整记录的一天不代表实际缺口。不预填个人资料或减重目标。

记录留存在当前设备；卸载会删除数据。CSV是导出存档，当前版本不支持导入、云同步、联网食物搜索或运动种类自动识别；支持健康连接步数读取，内置和自定义食物支持本地搜索。

## 构建

使用 Android Studio 打开项目，配置 JDK 17+ 与 Android SDK，然后执行：

```powershell
.\gradlew.bat assembleDebug
```

APK 输出：`app/build/outputs/apk/debug/app-debug.apk`。

应用包名 `cn.qingheng.app`。编译API36、目标API35、最低API26；AGP8.13.0、Kotlin2.2.20、Gradle8.14.3、JDK17+。步数使用稳定版 `androidx.health.connect:connect-client:1.1.0`，该库要求编译API36；健康连接功能需要Android9及以上及可用组件/数据源，Android8仍可手动填步数。构建首次需下载AndroidX依赖，缓存齐全后可加 `--offline` 构建。
